# Результати випробування бортового рішення на Raspberry Pi

Дата випробувань: 25–26.10.2026. Дані: `~/uav/flights/` на Raspberry Pi
(`beacon@raspberrypi.local`), журнал служби `~/uav/flights/onboard.log`,
бенчмарки `benchmarks/onboard/`. Налаштування стенда описано в
`docs/pi_onboard_bringup.md`.

## 1. Опис стенда

| Параметр | Значення |
|---|---|
| Обчислювач | Raspberry Pi 5 Model B Rev 1.1, 16 ГБ ОЗП, активне охолодження |
| ОС | Debian 13 (trixie), ядро 6.18.50+rpt-rpi-2712, aarch64; Python 3.13.5 |
| Камера | CSI, порт CAM0: Arducam 64MP OwlSight (сенсор OV64A40), оверлей `dtoverlay=ov64a40,clock-frequency=37125000,cam0`. Режим 1920×1080 @ 30 кадр/с, безперервний автофокус (`AfMode=2`) |
| Польотний контролер | ArduPilot **ArduPlane 4.6.2** (офіційний реліз, git `1ebd4d99`), тип `MAV_TYPE_FIXED_WING` |
| Зв’язок з ПК | MAVLink2, UART0 Raspberry Pi (GPIO14/15, `/dev/ttyAMA0`, `dtparam=uart0=on`), 115200 бод. Запитується `GLOBAL_POSITION_INT` @ 20 Гц і `SYSTEM_TIME` |
| Модель | YOLO26n, 512×512, NCNN FP32 (`yolo26n_512_visdrone_crops_v1_512_ncnn_model`), 3 класи: `person`, `vehicle`, `military_equipment`; поріг `conf` 0.25, `iou` 0.7; 3 потоки NCNN |
| ПЗ | ultralytics 8.4.189, torch 2.14.1+cpu, ncnn, picamera2 0.3.37, pymavlink |
| Бортова служба | `onboard/` як systemd-служба `uav-detector` (автозапуск); збереження кадрів у режимі `detections` з рамками; веб-сторінка live view (відео, карта, телеметрія, галерея) |

### Спосіб випробування

**Стендове випробування, без польоту.** Камера Raspberry Pi була спрямована
на телевізор, на якому відтворювалися відео з дронів з YouTube (1080p,
максимальна доступна якість). Польотний контролер лежав на столі, був
живлений і підключений до Raspberry Pi. 

### Тривалість

Усього 23 запуски (папки в `~/uav/flights/`). Основний запуск
`2026-10-26_11-41-32` тривав **51,7 хв** безперервно (54 139 оброблених
кадрів) у фінальній конфігурації: автофокус, 3 потоки NCNN, окремий
потік збереження кадрів.

### Висота і швидкість

Не застосовуються: стенд нерухомий. Висота відносно точки старту за даними
ПК (`rel_alt`, барометр): **2,9–3,7 м**, тобто дрейф барометра на столі.
Швидкість 0. GPS у приміщенні не мав фіксації (`fix_type 0`, 0 супутників),
тому координати в телеметрії й EXIF збережених кадрів дорівнюють
**0, 0**. Висоту польоту й швидкість, що відповідають реальним умовам,
моделює лише вміст відео на екрані (див. «Сцена»).

### Сцена (об’єкти в кадрі)

Екран телевізора з відео, знятими дронами:

- **Військові паради з повітря** (PLA 90 у Чжуріхе, парад до 250-річчя Армії
  США): колони танків, ПУ ракет, бронетехніки, стрій військових.
- **Аеродром Девіс-Монтен («boneyard»)**: ряди військових літаків з висоти.
- **Відео з FPV-дронів і дронів-розвідників** з фронту: техніка в полі,
  частина кадрів з накладками (логотипи, телеметрія, розмиття).

Через зйомку з екрана картинка гірша, ніж у реальному польоті: муар,
відблиски, менший динамічний діапазон, синій відтінок, кадр частково
займає кімната.

### Візуальна перевірка збережених кадрів (вибірка з 8 кадрів)

- Техніка на відео з FPV (танк, БТР) розпізнається як `vehicle` або
  `military_equipment` з впевненістю 0,48–0,69.
- Військові літаки на аеродромі позначено як `vehicle`, і в кадрі з
  десятками літаків знайдено лише кілька.
- **Хибні спрацьовування поза сценою:** мініатюри в меню YouTube з людьми
  отримали `military_equipment` (≈ 0,47). Тому частка «кадрів з детекціями» (44 %) **не є мірою
  точності**: розмітки для живого відео немає, і частина детекцій хибні.

## 3. Висновок щодо контрольного завдання

**Результати відповідають еталонним за швидкістю, точністю моделі та
стійкістю роботи на Raspberry Pi 5.** Не перевірено: політ, геоприв’язку з
реальним GPS, точність на живому відео.

| Критерій | Еталон | Отримано на Pi | Висновок |
|---|---|---|---|
| Точність моделі після перенесення на Pi | 0,541 / 0,298 (PyTorch) | 0,552 / 0,305 (NCNN на Pi) | **Відповідає**: різниця ≤ 0,011, у межах розбіжності між рушіями; втрат від NCNN і від Pi немає |
| Швидкість моделі | 23,43 FPS (Фаза 3) | 22,07 FPS | **Відповідає**: −6 %, той самий порядок; різниця пояснюється новішим ПЗ (trixie, ultralytics 8.4.189) |
| Швидкість повного конвеєра (камера → модель → телеметрія → запис) | ≥ 15 FPS | 16,6–18,7 FPS; 17,4 FPS протягом 51,7 хв | **Відповідає** з запасом ×1,7 |
| Стійкість ≥ 10 хв без тротлінгу | 0 прапорців, падіння FPS < 10 % | 51,7 хв, `0x0`, без пауз > 1 с | **Відповідає** |
| Прив’язка телеметрії до кадрів | телеметрія в кожному кадрі при працюючому ПК | 100 % (98,2 % при старті без ПК) | **Відповідає**; координати не перевірені (GPS без фіксації) |
| Якість детекції на живому відео | — (немає розмітки) | техніка розпізнається; є хибні спрацьовування поза сценою | **Якісно**: працює, але кількісно не оцінено |

Нижчий FPS повного конвеєра порівняно з бенчмарком моделі (17,4 проти
22,1) очікуваний: камера, підготовка кадру 1080p, MAVLink і запис JPEG
ділять ті самі 4 ядра. Для цього NCNN обмежено 3 потоками (без цього
FPS падав до ~10 під час запису кадрів).
